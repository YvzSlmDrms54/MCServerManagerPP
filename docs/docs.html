First launch

On first run, MCServerManager++ asks which language to use — Turkish or English — and creates a server folder next to the app. That folder is where everything lives: the Minecraft server itself, your world, backups, and the app's own settings.

Nothing is downloaded automatically yet. Place your existing server files — the server .jar and an accepted eula.txt — into the server folder before pressing Start. If the folder is empty, the app creates a short readme telling you what to add.

Server detection

MCServerManager++ looks at what's already in the server folder and works out what kind of server you're running — you don't have to tell it.

  • No versions folder → server isn't installed yet
  • A plugins folder → PaperMC
  • A mods folder → Fabric or Forge, checked further via the libraries folder and mod filenames
  • Neither → Vanilla

The result shows in the top-right corner of the main window at all times.

Language

The interface is fully bilingual — Turkish and English, chosen once on first launch and stored in the app's config. Menus, buttons, and every automated message (including Discord notifications) follow the selected language.

Console & commands

The main window streams server output live. Type into the command box at the bottom and press Enter or click Send to run any vanilla server command, exactly as you would in the server's own terminal.

Searching the console

Press Ctrl + F to open a search bar over the console. Enter jumps to the next match; Esc or Ctrl + F again closes it.

Server properties

Open Tools → Properties for a graphical editor over server.properties, organized into four tabs: General, Game Rules, Performance, and Security. Each control shows the underlying property key beneath it, so nothing is hidden from you — it's a faster way to reach the same file, not a different one.

Player management

Open Tools → Players for three tabs — OP, Whitelist, and Ban — each with an add/remove field and a live list read from the server's own ops.json, whitelist.json, and banned-players.json. These actions require the server to be running, since they're sent as real server commands.

Maintenance mode

Open Tools → Maintenance Mode to take the server offline for players without shutting it down. Turning it on:

  • Saves the current MOTD and whitelist state so they can be restored later
  • Sets a maintenance MOTD and enables the whitelist
  • Kicks any connected player who isn't an operator

Turning it off restores the saved MOTD and whitelist state exactly as they were.

Backups

Open Tools → Backup to zip the world folder on demand with Backup Now, or set a daily time and toggle automatic backups on. Every automatic backup runs save-all first and waits a moment before zipping, to avoid capturing a half-written world. A backup is also taken automatically whenever the server closes — planned or not — and the window keeps a running history of every backup made.

For a one-off backup without opening the window, use the Fast Backup button on the main screen.

Scheduled tasks

Open Tools → Scheduled Tasks to automate two things on a daily clock:

  • Restart — stops and restarts the server at a set time, useful for clearing memory on long-running servers
  • Maintenance window — turns maintenance mode on and off automatically between a start and end time

Discord webhooks

Open Tools → Webhooks to send server events to one or more Discord channels. Each webhook is configured independently:

  • A name and the channel's webhook URL
  • Which events to send: server started, server stopped, player joined, player left, backup completed, maintenance mode changed, server crashed
  • An optional mention — everyone, or a specific role ID

Messages are sent in whichever language the app is set to.

Discord access varies by region. If Discord is restricted on your network, webhook delivery will fail silently from the server's side — the app logs the connection error to the console rather than blocking anything else.

Crash detection

The app distinguishes a normal shutdown (you pressed Stop) from a crash (the process exited on its own). A crash prints a clearly marked block to the console and, if configured, sends a separate Discord notification — separate from the regular "server stopped" message, so you're not left guessing which one happened.

System tray

Closing the window doesn't quit the app — it minimizes to the system tray, where the server keeps running. Double-click the tray icon to bring the window back, or right-click it for Show, Stop Server, and Exit. Exit is the only action that actually closes the app.

Troubleshooting

"Unable to access file" / server won't start after a crash

If the server was force-killed rather than stopped normally, a java.exe process can be left running in the background holding a lock on the world folder. Open Task Manager, end any leftover java.exe processes, and start the server again.

Webhook messages aren't arriving

Confirm at least one event checkbox is ticked for that webhook, and that the URL was copied in full from Discord. If your network restricts Discord access, the message won't leave your machine — check the console for a connection error.

Antivirus flags the app after building

Some antivirus software inspects newly built executables the first time they run. This is a false positive common to freshly compiled .NET apps — allow it once, or add the app's folder to your antivirus exclusions.
